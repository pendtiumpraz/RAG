1. Folder Google Drive publik — tanpa login tanpa OAuth

Google Drive melayani pembacaan dengan API key biasa untuk berkas yang dibagikan “Siapa saja yang memiliki link”. Tidak ada layar izin, tidak ada token pengguna, dan — ini yang penting — tidak tersentuh verifikasi CASA yang selama ini menghambat mode akses penuh.

Hanya jalur ini yang bisa “satu folder, semua isinya ikut”

Pilih satu folder, dan seluruh berkas di dalamnya masuk — termasuk sub-folder, sub-sub-folder, sampai habis. Google Picker tidak bisa melakukan ini; alasannya di bagian 3.

Langkah untuk pengguna

  1. Buka folder di Google Drive → klik kanan → Bagikan.
  2. Pada “Akses umum”, ubah dari Dibatasi menjadi Siapa saja yang memiliki link, peran Pelihat.
  3. Klik Salin link.
  4. Di Nalar: Knowledge Base → Tambah sumber → jenis Google Drive — URL folder publik → tempel → Tambah & sync.
Tautan “hanya orang di organisasi ini” TIDAK bisa dipakai

Dari sisi API, folder semacam itu sama saja dengan tidak ada — jawabannya 404. Kalau kamu melihat pesan “Folder tak terlihat oleh publik”, inilah sebabnya yang paling sering. Setelan aksesnya harus benar-benar “Siapa saja yang memiliki link”.

Bentuk URL yang diterima:

https://drive.google.com/drive/folders/1A2b3C4d5E6f7G8h9I0j
https://drive.google.com/drive/folders/1A2b...?usp=sharing
https://drive.google.com/drive/u/0/folders/1A2b...
https://drive.google.com/drive/folders/1A2b...?resourcekey=0-xxxx
1A2b3C4d5E6f7G8h9I0j                    (id telanjang juga boleh)

Kalau yang tertempel adalah tautan berkas (/file/d/…), Nalar akan mengatakannya secara spesifik — bukan sekadar “URL tidak valid”. Buka foldernya, lalu salin URL folder itu.

Persiapan superadmin — sekali saja

Jalur ini butuh satu API key Drive milik platform:

  1. Google Cloud Console → project yang sama dengan OAuth client → APIs & Services → Library → aktifkan Google Drive API.
  2. Credentials → Create credentials → API key.
  3. Batasi kunci itu: API restrictions → hanya Google Drive API. Jangan pasang pembatasan HTTP referrer — kunci ini dipakai dari server, bukan browser.
  4. Nalar: Models & Keys → kredensial OAuth → baris Google → Ubah → isi Drive API key → simpan.
Kunci ini berbeda dari Picker API key

Picker API key memang dikirim ke browser dan dibatasi per-referrer. Drive API key dipakai server untuk membaca isi folder, jadi ia disimpan terenkripsi dan tak pernah keluar dari server. Jangan tukar keduanya.

2. Google Drive lewat akun tersambung

Dipakai kalau dokumennya tidak boleh dibagikan lewat tautan. Ada dua rasa, dan yang menentukan bukan pengaturan melainkan izin yang benar-benar diberikan akun itu saat menyambung:

IzinYang bisa dilakukanBeban verifikasi Google
drive.file
picker		 Hanya berkas yang dipilih pengguna lewat Google Picker. Berkas baru di folder tidak ikut otomatis. Ringan — bukan scope restricted.
drive.readonly
folder		 Satu folder beserta seluruh isinya, rekursif. Berkas baru ikut pada sync berikutnya. Berat — scope restricted: video demo + audit CASA tahunan berbayar.

3. Kenapa akun tersambung kadang tak bisa memilih berkas

Ini jebakan yang paling membingungkan, dan sekarang sudah dijelaskan di antarmuka alih-alih dibiarkan gagal diam-diam.

Izin sebuah akun ditetapkan saat akun itu disambungkan, dan tersimpan di token. Mengubah mode akses Drive di pengaturan tidak mengubah token yang sudah ada. Jadi setelah mode diubah, akun lama tetap tampak “tersambung” padahal tokennya tak memuat izin yang dituntut mode baru — Picker tak menemukan apa pun, dan tak ada pesan yang menerangkan sebabnya.

Sekarang: tambah izin, bukan putus-sambung

Nalar membaca izin yang benar-benar dimiliki tiap koneksi dan menawarkan tombol Tambah izin baca folder. Izin lama ikut terbawa ke token baru (include_granted_scopes), akun tak perlu dipilih ulang (login_hint), dan koneksi yang ada tidak perlu diputus.

Memilih folder di Picker tidak memberi akses ke isinya

Ini batas drive.file dari Google, bukan pengaturan yang bisa dinyalakan. Scope itu memberi akses per berkas. Kalau yang kamu mau adalah “klik satu folder, semua ikut”, pilihannya cuma dua: URL folder publik (tanpa verifikasi) atau drive.readonly (dengan verifikasi CASA).

4. SharePoint & OneDrive wajib OAuth

Microsoft tidak punya padanan API key untuk tautan publik. Endpoint /shares di Graph selalu meminta token — bahkan untuk tautan yang sudah dibagikan ke publik. Jadi tak ada jalur tanpa login di sisi Microsoft.

Persiapan superadmin

  1. Azure Portal → App registrations → daftarkan aplikasi.
  2. Redirect URI: https://<domainmu>/api/connections/microsoft/callback
  3. Certificates & secrets → buat client secret (maksimal 24 bulan — catat tanggal kedaluwarsanya).
  4. API permissions (delegated): Files.Read.All, Sites.Read.All, offline_access, openid, email.
  5. Nalar: Models & Keys → kredensial OAuth → baris Microsoft → Isi → Client ID, secret, dan Directory (tenant) ID. common berarti akun kerja maupun pribadi.

Bentuk masukan yang diterima

BentukContohYang diambil
URL situs https://perusahaan.sharepoint.com/sites/Marketing Document library utama situs, rekursif
URL folder di library …/sites/Marketing/Shared Documents/Kebijakan Folder itu beserta seluruh sub-foldernya
Tautan berbagi https://perusahaan.sharepoint.com/:f:/s/Marketing/Ex4mpl3… Folder yang ditunjuk tautan, rekursif
Dikosongkan — OneDrive pribadi akun yang tersambung
“Shared Documents” ditangani otomatis

Di URL SharePoint, library Documents muncul sebagai Shared Documents. Nalar mencocokkan keduanya, sehingga Shared Documents/Kebijakan tidak salah dicari sebagai folder bernama “Shared Documents” di dalam library Documents — kekeliruan yang selalu berujung 404.

Akun yang tersambung harus punya akses ke situsnya

Nalar membaca atas nama pengguna (delegated), bukan sebagai aplikasi dengan hak penuh. Kalau akun itu tak bisa membuka situsnya di browser, Nalar juga tidak bisa. Pesan galatnya akan menyebut hal ini apa adanya.
