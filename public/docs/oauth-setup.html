Panduan OAuth

Menghubungkan Google Drive dan Microsoft OneDrive / SharePoint ke Nalar — untuk login sosial sekaligus sinkronisasi dokumen.

Status saat ini di produksi: BELUM AKTIF belum

Diperiksa pada rag.sainskerta.net: hanya provider credentials (email + password) yang terdaftar. GOOGLE_CLIENT_ID dan MS_CLIENT_ID belum ada di environment Vercel, sehingga NextAuth melewatkan kedua provider itu sepenuhnya — 0 akun terhubung, 0 sumber data.

Selama belum dipasang, dokumen tetap bisa dimasukkan lewat POST /api/ingest.

1. Kenapa ada DUA redirect URI per provider

Ini bagian yang paling sering terlewat dan menyebabkan galat redirect_uri_mismatch. Nalar memakai OAuth untuk dua keperluan berbeda, dan masing-masing punya alamat callback sendiri:

KeperluanDitanganiRedirect URI
Login ke dashboard NextAuth {NEXTAUTH_URL}/api/auth/callback/google
{NEXTAUTH_URL}/api/auth/callback/azure-ad
Menghubungkan akun storage (bisa banyak akun, tanpa mengubah sesi) modules/connections {NEXTAUTH_URL}/api/connections/google/callback
{NEXTAUTH_URL}/api/connections/microsoft/callback
Daftarkan KEDUANYA

Kalau hanya yang pertama, login jalan tapi tombol “Connect Google” di halaman Knowledge akan gagal — dan sebaliknya. Perhatikan juga bahwa jalur kedua memakai microsoft, bukan azure-ad.

NEXTAUTH_URL menentukan redirect URI

Alamat callback dibentuk dari variabel itu (lihat oauth-flow.ts). Kalau isinya tidak persis sama dengan yang didaftarkan — beda http/https, ada garis miring di ujung, atau masih localhost — OAuth akan ditolak.

Produksi: https://rag.sainskerta.net

2. Google — Drive

2.1 Buat project & aktifkan API

  1. Buka Google Cloud Console, buat project baru (mis. Nalar RAG).
  2. APIs & Services → Library → aktifkan Google Drive API. Tanpa ini, token terbit tapi setiap panggilan Drive dibalas 403.

2.2 OAuth consent screen

  1. APIs & Services → OAuth consent screen.
  2. User type: External (kecuali seluruh pengguna berada di satu Google Workspace).
  3. Isi nama aplikasi, email dukungan, dan domain sainskerta.net.
  4. Pada Scopes, tambahkan tepat tiga ini: 
    openid
email
https://www.googleapis.com/auth/drive.readonly
https://www.googleapis.com/auth/drive.file
Kenapa dua scope Drive

drive.readonly untuk MEMBACA dokumen pengguna jadi bahan knowledge base. drive.file untuk MENULIS balik vault memory ke folder _nalar-memory/ — scope ini hanya memberi akses pada berkas yang dibuat aplikasi ini sendiri, bukan seluruh Drive.

Scope Drive itu “sensitive” — verifikasi Google

Selama aplikasi berstatus Testing, hanya akun yang kamu daftarkan di Test users yang bisa memakainya (maks. 100). Untuk membukanya ke publik, Google mewajibkan proses verifikasi yang bisa memakan waktu berminggu-minggu. Untuk pemakaian internal, cukup tetap di Testing dan daftarkan akunmu.

2.3 Buat OAuth client

  1. Credentials → Create Credentials → OAuth client ID.
  2. Application type: Web application.
  3. Authorized redirect URIs — masukkan KEDUANYA: 
    https://rag.sainskerta.net/api/auth/callback/google
https://rag.sainskerta.net/api/connections/google/callback
    Untuk pengembangan lokal, tambahkan juga: 
    http://localhost:3000/api/auth/callback/google
http://localhost:3000/api/connections/google/callback
  4. Simpan Client ID dan Client secret.

2.4 Yang diminta aplikasi saat login

ParameterNilaiAlasan
access_typeoffline agar terbit refresh token — tanpa ini sinkronisasi mati begitu access token kedaluwarsa (±1 jam)
promptconsent (login)
select_account consent (connect)		 memaksa refresh token terbit ulang, dan pada jalur connect membuat pengguna bisa memilih akun berbeda sehingga bisa menghubungkan banyak akun

3. Microsoft — OneDrive / SharePoint

3.1 Daftarkan aplikasi

  1. Buka Microsoft Entra admin center → App registrations → New registration.
  2. Nama: Nalar RAG.
  3. Supported account types: pilih Accounts in any organizational directory and personal Microsoft accounts bila penggunanya lintas organisasi. Pilihan ini menentukan nilai MS_TENANT_ID di langkah berikutnya.
  4. Redirect URI → platform Web, masukkan KEDUANYA: 
    https://rag.sainskerta.net/api/auth/callback/azure-ad
https://rag.sainskerta.net/api/connections/microsoft/callback

3.2 Client secret

  1. Certificates & secrets → New client secret.
  2. Salin kolom Value (bukan Secret ID) — nilainya hanya muncul sekali.
Secret Microsoft punya masa berlaku

Maksimal 24 bulan. Saat kedaluwarsa, login dan sinkronisasi berhenti tanpa perubahan kode apa pun. Catat tanggalnya sekarang.

3.3 API permissions

  1. API permissions → Add a permission → Microsoft Graph → Delegated permissions.
  2. Tambahkan: 
    openid
email
offline_access
Files.Read
  3. Klik Grant admin consent bila akunmu admin direktori.
Files.Read mencakup SharePoint

Nalar mengakses OneDrive maupun SharePoint lewat endpoint Microsoft Graph yang sama (/me/drive), jadi tak ada izin terpisah untuk SharePoint. Untuk menunjuk pustaka dokumen tertentu, isi folderPath saat menambahkan sumber data di halaman Knowledge.

3.4 Menentukan MS_TENANT_ID

NilaiKapan dipakai

organizationshanya akun kerja/sekolah
GUID direktoridikunci ke satu organisasi saja

  GOOGLE_CLIENT_SECRET  = GOCSPX-...

Wajib redeploy

Environment variable hanya terbaca saat build/boot. Setelah menyimpannya, jalankan Redeploy — tanpa itu provider tetap tidak muncul dan kamu akan mengira konfigurasinya gagal.

Lokal

GOOGLE_CLIENT_SECRET=
MS_CLIENT_ID=
MS_CLIENT_SECRET=

5. Verifikasi

Cara tercepat memastikan provider benar-benar terdaftar — endpoint ini publik dan tidak membocorkan apa pun:

curl -s https://rag.sainskerta.net/api/auth/providers

Sebelum dikonfigurasi, balasannya hanya berisi credentials. Setelah berhasil, google dan/atau azure-ad ikut muncul.

Urutan pengecekan yang disarankan

1. /api/auth/providers memuat provider baru → 2. tombol “Lanjut dengan Google” muncul sendiri di /auth → 3. login berhasil → 4. di Knowledge, tombol “Connect Google” muncul → 5. akun tampil di daftar, lalu tambahkan sumber data dan jalankan Sync.

6. Perilaku saat env belum ada

Aplikasi sengaja tidak menawarkan sesuatu yang pasti gagal. Tanpa env OAuth:

BagianPerilaku
Halaman /auth tombol Google/Microsoft tidak ditampilkan (dicek lewat /api/auth/providers); pemisah “ATAU EMAIL” ikut disembunyikan sehingga formulir email tampil bersih
Halaman Knowledge tombol “Connect …” disembunyikan, diganti keterangan beserta tautan ke panduan ini (/api/connections/providers)
/api/connections/{provider}/start balas 400 dengan pesan “… OAuth belum dikonfigurasi (env)”
Login email + password tetap berjalan penuh — OAuth sepenuhnya opsional
Memasukkan dokumen lewat POST /api/ingest; hanya sinkronisasi Drive/SharePoint yang belum tersedia
Satu provider saja boleh

Google dan Microsoft berdiri sendiri. Memasang Google saja sudah membuat login Google dan sinkronisasi Drive berfungsi, tanpa menyentuh Microsoft.

7. Kalau gagal

GejalaSebab yang paling sering
redirect_uri_mismatch redirect URI belum didaftarkan, atau NEXTAUTH_URL tidak persis sama (beda skema/garis miring). Ingat: dua URI per provider.
Tombol tetap tak muncul setelah env diisi belum redeploy — env hanya terbaca saat boot
Login jalan, tapi “Connect Google” gagal URI /api/connections/google/callback belum didaftarkan
access_denied di Google aplikasi masih Testing dan akun itu belum masuk Test users
Sinkronisasi jalan sekali lalu berhenti tak ada refresh token — pastikan access_type=offline dan hapus izin lama di akun Google agar consent terbit ulang
Drive 403 padahal login sukses Google Drive API belum diaktifkan di project
Microsoft tiba-tiba berhenti setelah berbulan-bulan client secret kedaluwarsa (maks. 24 bulan)
Jangan pernah menaruh client secret di kode atau repo

Keduanya hanya boleh ada di environment. Token OAuth pengguna yang tersimpan di database sudah dienkripsi AES-256-GCM dengan CREDENTIALS_ENCRYPTION_KEY dan tak pernah dikirim ke browser.
