Yang bisa dilakukan

Setiap fitur yang kamu minta, dan di mana kodenya hidup.

Embeddings

Pilih model bebas

Lokal ~80MB, ~2GB, atau API OpenAI/Cohere. Ganti dari Settings. Hanya satu aktif per tenant.

Storage

Model dari Drive/SharePoint

File model embedding di-host superadmin, diunduh sekali, di-cache, dipakai bersama.

LLM

Semua provider terbaru

Anthropic, OpenAI, Google, Mistral, DeepSeek, xAI, Groq, Cohere — daftar per 23 Jul 2026.

Keys

API key tersimpan aman

Terenkripsi AES-256-GCM saat disimpan. Per tenant, atau fallback env untuk on-prem.

History

Riwayat lengkap

Semua percakapan & pesan tersimpan per chatbot, dengan sitasi sumber tiap jawaban.

Embed

Chatbot di mana saja

Satu baris <script>, respon streaming token-per-token via SSE, warna & origin bisa diatur.

Sources

Drive per-user

Tiap user hubungkan Google Drive / SharePoint miliknya sendiri sebagai sumber pengetahuan.

Multi-bot

1 user, banyak chatbot

Tiap chatbot = 1 ID = 1 KB terisolasi. ID beda ⇒ pengetahuan beda.

Deploy

SaaS & on-prem

Satu perintah docker compose up untuk on-prem air-gapped, atau mode SaaS multi-tenant.

04

Isolasi tenant

Wajib: antar tenant tidak boleh saling connect. Dipaksa oleh database, bukan sekadar kode app.

Row-Level Security

Setiap baris punya tenant_id. withTenant() menyetel GUC app.current_tenant, dan policy Postgres memaksa filter di level DB. Bug di kode app tidak bisa membocorkan baris antar tenant.

Basis pengetahuan tiap chatbot juga difilter chatbot_id — jadi satu user pun tidak mencampur KB antar chatbot-nya sendiri.

-- migrations/0001_rls.sql CREATE POLICY tenant_isolation ON documents USING (tenant_id = app_current_tenant()) WITH CHECK (tenant_id = app_current_tenant()); // setiap query berjalan di dalam: withTenant(tenantId, async (tx) => { // SELECT tanpa WHERE tenant pun // tetap terkurung ke tenant ini. });
05

SaaS & on-prem

Satu basis kode, dua mode via DEPLOYMENT_MODE.

mode = saas

SaaS multi-tenant

Signup terbuka, tiap pendaftar dapat tenant baru terisolasi. Tiap user hubungkan Drive-nya sendiri; file model embedding pakai Drive superadmin bersama. Billing & kuota per plan.

mode = onprem

On-prem / air-gapped

docker compose up → Postgres+pgvector + app. Satu organisasi, satu tenant. Embedding lokal (80MB/2GB) tanpa panggilan keluar. Key organisasi via env.

06

Pertanyaanmu, dijawab

Semua "bisa gak" dari brief awal.

Embeddings pakai Google Drive superadmin, bisa gak?

Bisa. Yang di Drive superadmin adalah file MODEL embedding (ONNX 80MB/2GB) — diunduh sekali, di-cache, dipakai bersama semua tenant. Hasil embedding (vektor) tiap tenant tetap terisolasi, tidak pernah bercampur.

1 user = 1 ID chatbot yang bisa di-embed ke website lain, beda ID beda knowledge base?

Bisa. Satu user boleh punya banyak chatbot; tiap chatbot punya publicKey sendiri. Retrieval selalu difilter chatbot_id, jadi beda ID = beda KB terisolasi.

Setiap user konek Google Drive masing-masing?

Ya. Sumber data per-user pakai OAuth Drive/SharePoint milik user itu sendiri.

Antar tenant harus terisolasi, tidak boleh saling connect?

Dipaksa di level database lewat Postgres Row-Level Security + tenant_id. Kebocoran antar tenant mustahil walau ada bug di kode.
